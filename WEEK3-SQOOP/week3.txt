--SQOOP EXECUTION FLOW ---

GET METADATA OF THE TABLE BY RUNNING SIMPLE QUERY LIMIT 1 (INFER THE DATA TYPES)

BUILD THE POJO (PLAIN OLD JAVA OBJECT) CLASS WITH APPROPRIATE GETTERS AND SETTERS

COMPILE THE POJO CLASS INTO JAR FILES

RUN BOUNDARY QUERY RO GET MIN AND MAX BY SPLIT COLUMN (DEFAULT IS PK COLUMN)

COMPUTE THE SPLIT SIZE

DIVIDE IT WITH NO OF MAPPERS AND COMPUTE SPLITS

SUBMIT THE MR JOB WITH NO OF MAPPERS EQUAL TO 4 BY DEFAULT

EACH MAP TASK WILL THE SELECT QUERY ON THE SOURCE TABLE WITH WHERE CONDITION BASED ON THE SPLIT TO READ THE DATA

DATA WILL BE WRITTEN TO THE FILES IN THE LOCATION MENTIONED

LETS SAY WE HAVE THE HDFS FILE WITH 53292 RECORDS AND DOING SQOOP EXPORT TO RDBMS AND WE HAVE THE JOB FAILED.

EVEN THOUGH JOB FAILED IT LOADED 200 RECORDS TO THE RDBMS TABLE.

IDEALLY WE EXPECT NOTHING LOADED TO THE RDBMS TABLE

EITHER TRANSFER ALL OR LOAD NOTHING BUT NOT PARTITIAL DATA LOADED.

BASED ON THIS WE NEED TO CHECK TWO THINGS.

1 - WHY THE JOB FAILED?

CAN BE SEEN FROM TRACKING URL 

2 - IF A JOB FAILS HOW TO MAKE SURE THAT TARGET TABLE IS NOT IMPACTED (PARTIAL LOAD)

THIS IS WHERE THE STAGING TABLE CONCEPT WILL COME INTO PICTURE

CREATE TABLE CARD_TRANSACTIONS_STAGE
(
CARD_ID BIGINT,
MEMBER_ID BIGINT,
AMOUNT INT(10),
PASSCODE INT(10),
POS_ID BIGINT,
TRANSACTION_DT VARCHAR(255),
STATUS VARCHAR(255),
PRIMARY KEY (CARD_ID,TRANSACTION_DT)

SQOOP EXPORT \
--CONNECT "JDBC:MYSQL://10.0.2.15:3306" \
--USERNAME RETAIL_DBA \
--PASSWORD CLOUDERA \
--STAGING-TABLE CARD_TRANSACTIONS_STAGE \
--TABLE CARD_TRANSACTIONS \ -- RDBMS TABLE
--EXPORT-DIR /HDFSPATH/DATA/FILE.CSV \ -- HDFS PATH WHERE THE FILES ARE
--FIELDS-TERMINATED-BY ','

NOW IN THIS CASE STAGING TABLE WILL ONLY BE IMPACTED BUT NOT THE FINAL TABLE

ONCE THE JOB IS SUCCEEDED , ALL THE RECORDS FROM STAGING TABLE WILL BE MIGRATED TO FINAL TABLE

STAFING WILL BE TRUNCATED AFTER SUCCESSFUL MIGRATION TO FINAL TABLE

SQOOP IMPORT \

FIRST IT WILL IMPORT EVERYTHING AND THEN IT WILL START MERGING PROCESS.

SINCE MERGING IS INVOLVED IT IS A MR JOB AND WE WILL SEE FILE NAME PART_R_00000

THIS WILL MAKE SURE EACH PK RECORD WILL ONLY AVAILABLE AT ONCE AND LATEST TIMESTAMP WILL BE CONSIDERED.


2 MODES -------

1.APPEND - WE TALK ONLY ABOUT NEW INSERTS AND WILL NOT WORK UPDATES

--LAST-VALUE 0

2.LASTMODIFIED - WHEN WE HAVE BOTH INSERTS AND UPDATES


--INCREMENTAL LASTMODIFIED
--LAST-VALUE 0

2.i) 

--append -- maintain multiple rows per PK record with varying timestamps

1. Dynamically coalescing shuffle partitions
=============================================
1) 

lets say we configured spark.shuffle.partitions=10 but but we only have data for 5 partitions 
then we still get 10 tasks created though there is no data in other 5 partitions.

bit overhead on Yarm RM to allocate resources and monitor those.

this problem will be resolved by AQE.

when we enable the AQE, spark can findout all the partitions related information during data shuffling activity and it will try to adjust the 
spark.shuffle.partitions property dynamically and also it will try merge the small partitions into bit big one. (to make all of them proportionate)

if our partitions are small in the number:

	we end up having large partitions size.
	tasks needs large amount of memory
	may cause OOM exception
	
if our partitions are big in the number:
	small / tiny partitions size
	many network fetch causing inefficient network I/O
	more burden for spark task schedular

	
2)

 lets take above 5 partitions which has data and those 5 partitions are not equal in the sense of
few partitions may take longer time where as few might take few milli secs but whole job should be waited to complete everything.

this represents a data skew problem.

===coalesce===
- can only minimize the shuffle but, it is not always guaranteed that it will avoid full shuffle
- resultant partitions will be of varying size

ex: df.coalesce(5) - It will enforce the spark.sql.shuffle.partitions value to 5 from 200 (default partitions size)

===repartition===
- does full shuffle
- resultant partitions will be of same size

ex: df.repartition(5) - It will preserve the spark.sql.shuffle.partitions value and does join on 200 partitions (default partitions size)



scenario 1: Joins
==================

resultant_df = emp_df.join(sal_df,"id")

df.coalesce(5) - It will enforce the spark.sql.shuffle.partitions value to 5 from 200 (default partitions size)
here join happens only in 5 partitions
df.repartition(5) - It will preserve the spark.sql.shuffle.partitions value and does join on 200 partitions (default partitions size)
here join happens in 200 partitions so it is faster.

repartition execution time: 12.25 secs
coalesce execution time: 15.16 secs

scenario 1: count action
=========================

rdd = sc.textFile("logs.txt") - 2.7GB file
rdd.getNumPartitions=22

spark schedulers
=================

typical case, jobs in spark application are run seqentially

however we can try to run them parallelly assuming there is no dependency


df1 = spark.read.json("/data/d1")
df2 = spark.read.json("/data/d2")

print(df1.join(df2,"id","inner").count()

df3 = spark.read.json("/data/d3")
df3 = spark.read.json("/data/d4")

print(df3.join(df4,"id","inner").count()

by default these two actions will create two jobs and run them in seqentially even though there is no dependency between the actions.


from pyspark.sql import SparkSession
import threading

def do_job(f1,f2):
	df1 = spark.read.json(f1)
	df2 = spark.read.json(f2)
	outputs.append(df1.join(df2,"id","inner").count())
	
if __name__ == "__main__":
	spark = SparkSession \
			.builder \
			.appName("Demo") \
			.master("local[*]) \
			.config("spark.schedular.mode", "FAIR") \
			.getOrCreate()

file_prefix = "data/d"
jobs = []
outputs = []

for i in range(0,2):
	file1 = file_prefix + str(i + 1)
	file2 = file_prefix + str(i + 2)
	thread = threading.Thread(target=do_job, args=(file1, file2))
	jobs.append(thread)
	

for j in jobs:
	j.start()
	
for j in jobs:
	j.join()

print(outputs)


since tasks are running parallelly we need resources to be allocated same time and these will end up being in the competition for resources

how do we avoid it?

bydefault :

spark runs its jobs in FIFO fashion

. first job gets highest priority
. consumes as much as needed
. then next jobs gets priority once the first one is over.

FAIR:

spark.schedular.mode= FAIR
round robin slot allocation
	assign one task in a slot from first job then 
	assign one task in a slot from second job

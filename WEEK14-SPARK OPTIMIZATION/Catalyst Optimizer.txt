Catalyst Optimizer
====================

Structured API's (DF, DS, Spark SQL) perform better than raw RDD's

Catalyst Optimizer will optimize the execution plan for structured API's

Rule based optimization.

many rules are already available. Also if we want we can add our own optimization rules.

	.format("csv") \
	.option("header",true) \
	.option("inferSchema",true) \
	.option("path","students.csv")
	.load()

df1.createOrReplaceTempView("students")

spark.sql("select *from students").show()

1. unresolved/parsed logical plan

	our query is parsed and we get unresolved logical plan (checks for syntax errors)

	in this it checks for any of the syntax errors. if syntax errors are there then it throws parsed exception
	
	ex: spark.sql("select *frm students").show() //from keyword
	
	if syntax is correct.

2. Resolved / analyzed logical plan

	in this case it checks table names, column names from catalog (place where metadata kept)
	
	if all are correct here like table names and column names then it will go next step.
	
3. Optimized logical plan.

	catalyst optimizer will come into the picture
	
	- predicate pushdown
	- combining of filters
	- combining of projections
	 
	 there are many such rules which are already in place.
	 
	 if we want we can add our own rules in the catalyst optimizer.
	 
	 consider you are doing a aggregate.
	 
	 as per the logical plan lets say it says we have to do aggregate.
	 
	 in the physical plan ..
	 
4. physical plan

	plan 1 - sort aggregate
	plan2 - hash aggregate
	
	it will select the physical plan which is the most optimized one with minimum cost.
	
	
	this selected physical plan is converted to lower level API's RDD code.
	
	if we directly write our code in lower level API's like RDD then catalyst optimization wont come into the picture.

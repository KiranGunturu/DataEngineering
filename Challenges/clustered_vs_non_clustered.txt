SEEK AND SCAN

SEEK - QUITE IS GENERALLY FASTER THAN SCAN (when there is an index)
SCAN - when there is not an index it will go for full table scan.

clustered index:

orders table (order_id is the PK)

PK - by default clustered unique index

lets say we inserted order_id=5 first,order_id=4 second then order_id=6

order_id=4
order_id=5
order_id=6

it will make sure that physical order of the data is maintained and sorted in assecnding.

clustered vs non-clustered:

PK is on order_id
PK can be on (order_id,customer_id) and it is of composite PK.
when we serach on order_id, our serach will be faster as it is having index on it.
if we also want to have more freqent searches then we can create non-clustered index on it - where the indexing info will be maintained in a different place than 
where the actual data is present.
non-clustered will require little extra storage.

only one clustered index is possible on table because we can't have more than one type of maintaning physical order or the table.

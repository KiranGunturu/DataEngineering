cache & persist
================

we have 8 GB file.

val random = new scala.util.Random
val start = 1
val end = 60

val rdd1 = sc.textFile("biglogNew.txt")

val rdd2 = rdd1.map(x => {
var num = start + random.nextInt( (end -start) + 1)
(x.split(":")(0) + num,x.split(":")(1))

}
)

val rdd3 = rdd2.groupByKey

val rdd4 = rdd3.map(x=> (x._1, x._2.size))

here we get something like below

ERROR1,5
ERROR10,19
WARN46,20
WARN2,67


val rdd5 = rdd4.map(x=> {
if(x._1.substring(0,4) == "WARN")
("WARN",X._2)
ELSE
("ERROR",X._2)
}
)

ERROR,5
ERROR,19
WARN,20
WARN,67


val rdd6 = rdd5.reduceBykey(_+_)

rdd6.collect.foreach(println)

ERROR,24
WARN,87

this code will create 3 stages stage0, stage1, stage2 as we have two wide transformations which are groupByKey and reduceBykey.

lets say we just executed below action again.

rdd6.collect.foreach(println) - as spark has some internal optimization it just execute only last stage which is stage2 and mark other two stages as skipped.

lets say we just executed below action again.

rdd5.collect.foreach(println) - as spark has some internal optimization it just execute only last stage which is stage1 and mark other stage as skipped. 13 secs

if we run the same action again it will still take 13 secs.

even if we run that multiple times it will still take 13 secs.

now lets cache rdd4 


rdd4.cache

now run an action so that rdd4 will get cached.

rdd5.collect.foreach(println) now it will still take 13 secs as it just cachcing the rdd4 now and doing the operatins.

now if we see storage tab it will show the cache.

now if we run again below action 

rdd5.collect.foreach(println) - now the results are given instantly almost with 0.3 secs

rdd4.unpersist() - to remove from cache.

now what if I want to persist

rdd4.persist

rdd5.collect.foreach(println) - as it was unpersisted earlier, now it will still take 15 secs as it just cachcing the rdd4 now and doing the operatins.

rdd4.persist(StorageLevel.DISK_ONLY) - Persisted to disk and serialized

rdd5.collect.foreach(println) - it will take slightly bit longer than cache as it has to stored into disk - 4 secs.

if we run again rdd5.collect.foreach(println) - takes 83ms

the size of file was 8.2Gb on disk(serialized form it is 8.2 GB)

when we talk about memory data is kept in deserialized form then it may become 20Gb roughly.

SERIALIZED MEANS IT BYTES FORM - AND IT TAKES A BIT OF TIME BECAUSE IT HAS TO BE DESerialized

deserialize is fast and takes more space as data is kept in the form of objects.

==============


Interms of serializer we should prefre kryo serializer over java serializer.

whenever the data is stored on disk or has to be transfered over the disk it has be in serialized form.

if we use kryo serializer then size will be much lesser than in the case of java serializer.

if we have 5gb then we might end up transerfeing around 2gb with the help of kryo serializer

kryo is significantly faster and more impact than java serializer (often as much as 10 times as per the documentation)

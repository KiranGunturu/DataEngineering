============
partitioning
============

consider an e-commerce site with orders coming across the US.

500 mb data

and 4 node cluster

so 500 mb divided into 4 parts across the cluster.

select *from orders where state='WA';

when this query run parallelly on 4 blocks which are sitting on 4 nodes.

now all records on each machine need to be scanned to get WA records.(we are not skipping anything)

lets say we have 4TB instead of 500 mb then scanning all records will take significant time.

if US has 50 states then there will be 50 dirs which are created using partition on state.

data is orders table is logically divided into smaller parts

each part will hold data for each state.

lets say we have 4 states then 4 folders will be created on all 4 nodes

when cardinality is very low then we go for partitioning otherwise we end up creating more folders which gets more burden on name node.

2 types

1.static partitioning
2.dynamic partitioning

in static partitioning we should have an idea of our data abd we should be loading each partition manually. this is tedious process.

in dynamic partitioning, partitions are created automatically without manual loading.

when we do not know data in advance then we go with then we go with dynamic partitioning

when we already know the data well then we go with static partitioning.

static partitioning however is faster than dynamic partitioning as system will take time to understand the data and automate.

dynamic partitioning:

to allow dynamic partitioning which is by default disabled

in hive:

set hive.exec.dynamic.partition=true;
set hive.exec.dynamic.partition.mode=nonstrict;

generally dynamic partition is a 3 step process.

1.create normal table without any partition and have the data loaded in it. (table1)
2.create the partitioned table with partition on a column name. (table2)
3. transfer the data from normal table to partitioned table. (from table1 to table2)

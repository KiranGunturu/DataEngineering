difference between groupByKey and reduceByKey

both are wide transformations

============
reduceByKey
============

we will advanage of local aggregation

	1. more work in parallel
	2. less shuffling required
	
we can think this same as combiner acting at the mapper end.
before sending to the reducer first it will do the local aggregation will happen on local machine.

===========
groupByKey
===========

we do not get any local aggregation

all the key value pairs are shuffled to another machine.

so we have to shuffle more data and less parallesim

always prefer reduceByKey and never use groupByKey.

consider we have 1 TB data sitting in hdfs

1000 node cluster

how many partitions will be there in our rdd?

1 TB / 128 = 8000 blocks

so rdd will have 8000 partitions.

on each node we might end up getting 8 partitions.

lets say we have the following data in all of our 1000 nodes

Node1:

WARN: Tuesday 4 september 0405

ERROR: Tuesday 4 september 0405

ERROR: Tuesday 4 september 0405

if we apply groupByKey 

all the WARNs will go on one machine
all the ERRORs will go on one machine
all the INFOs will go one machine

at the max if we have 3 distinct keys then we will have maximum 3 machines which hold all our data.

before applying groupByKey we have our data well distributed across 1000 machines

but now after using groupByKey we have data distributed across at the max three machines

we are restricting parallesim though we have 1000 nodes cluster

3 machines hold 1 TB data in memory that means we have a huge posibility of out of memory error.

we will get only 3 partitions (max) which are full and can lead to out of memory error.

can you tell me that transformation which can lead to out of memory error ? that is groupByKey

Even if we do not out of memory error then also it is not suggested to use groupByKey

because we are restricting out parallesim

so we should never use groupByKey


no of jobs is equal to no of actions

no of wide transformations is equal to no of stages + 1

no of partitions is equal to no of tasks

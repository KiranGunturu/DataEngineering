To improve resiliency, we deploy the servers in two availability zones, by using an auto scaling group and an application load balancer and we deploy NAT gateway in both availability zones.
For additional security, we deploy the servers in private subnets.
The servers receive requests through the load balancer.
The servers can connect to the internet by using a NAT gateway.

Auto scaling - scale based on the incoming traffic
    we should first create the auto scaling templete and use it. template will ask us info like starts with, min and max instances to scale based on the traffic
    we can specify in what VPC and in what subnets we want these ec2 instances to be scaled
    once we create the auto scaling group, ec2 instances will be created based on the numver we speicfied in starts with secction of scaling templete.
    in this example we provisioned ec2 instances in private subnet, they will not have public ip so we use bastion or jump host.


Bastion host - if we want to access EC2 instance (no public ip) hosted on private subnet, we will create jump / bastion host (EC2 instance) in the public subnet then connect to EC2 which is in the private subnet

use below to copy pem file from local to bastion host
scp -i /User/Downloads/aws_login.pem /User/Downloads/aws_login.pem ubuntu@34.121.33.12:/home/ubuntu

then do ssh to ec2 instance which is in private subnet from bastion
ssh -i aws_login.pem ubuntu@34.121.66.0


Load balancer - balances the load between multiple servers
   internet facing  -  routs requests from clients to targets over the internet. requires public subnet
    nternel facing - routs requests from clients to targets using private ip addresses
    we should create the target group - can be ec2 instances, ip addresses, lambda function
when we create the load balancer, we should attach the target target group created above

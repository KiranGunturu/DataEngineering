VPC
    Define cidr to get range of ip addresses
    subnets within the VPC
    subnet - partition of a VPC
    private and public subnets
    private subnets - do not have internet connectivity
    public subnets - do have connectivity to internet
    internet gateway - component that allows communication between your VPC and the internet
        enables inbound and outbound access to the internet
        not a physical device
        one to one mapping between VPC and internet gateway (one igw per one VPC)
        NO cost
        different than NAT gateway
    NACL - to allow or deny traffic at the subnets level
        we can create inbound and outbound at one subnet and we can assign them to multiple subnets as well
    lets say we created an EC2 instance in the public subnet of VPC - 
        by default, at the security group level, aws will deny all inbound traffic to that ec2 instance and allow all outbound traffic except port 25 (SMTP)
    so this is like securiting our systems both at the subnet level and also individaul EC2 instacnes where teams will host their apps
    security rules at the subnet level takes precedence.
    security rules at the security group level with lowest rule number takes the effect.
        ex: rule number 100 - traffic as allow will take precedence on rule number 101 - traffic as deny
    
    NAT gateway - ip masking - act as a bridge between private subnet anb internet gateway
        ex: lets say if there is a RDS instance which is in private subnet and it wants to communicate to internet for getting patches / updates.
        they can't just communicate directly with igw as they will not have punlic ip addresses
        so the request first gies to NAT gateway which is on public subnet (ip masking will be done) - goes to internet gateway then public internet. samething when traffic coming inbound for this request
        direct inbound traffic from public internet to private subnet is not allowed 
    if an EC2 instance hosted in public subnet wants to communicate to internet, this will not go directly but will go thru internet gateway. In this case, NAT transalation happens at the igw

    Route tables - holds lot of rules to distribute the traffic from internet gateway to subnets or viceversa

    vpc cidr - 10.0.0.0./16
    route table
    ===========
    destination     target
    10.0.0.0/16     local
    0.0.0.0/0       igw
 
    destination 10.0.0.0/16 means whenever someone wants to communicate that matches this criteria (10.0.0..0/16) then it should goto local
    meaning instance to instance communication within the VPC is allowed

    destination 10.0.0.0/0 means whenever someone wants to talk public internet, we are gonna pass thru igw

    when we create a VPC in aws - aws will by default create subnets (4 subnets, one private and public in two AZs with in same region), route tables, internet gateway and s3 end point.

    cidr range - 10.0.1.0/8 - 16,771K ips (255*255*255)
    cidr range - 10.0.1.0/16 - 65,536 ips (255*255)
    cidr range - 10.0.1.0/24 - 256 ips (255)
     cidr range - 10.0.1.0/32 - 1 ip

    Lets say if we want to connect to S3 from ec2 instance which is in private subnet -
        there are two ways.
        1) EC2 instance can't just communicate directly s3 but thur igw
        so the request first gies to NAT gateway which is on public subnet (ip masking will be done) - goes to internet gateway then public internet then to s3
        so here we are technically leaving VPC and also aws cloud and reaching s3 over the internet

        2) other is to connect to s3 from within vpc instead over the public internet
            this reduces latency and very secure
    
    why s3 is outside of vpc -
        aws s3 buckets are designed to be outside of VPC because s3 is intended to be a global service that can be accesses from anywhere on the internet.
        by keeping s3 outside of vpc, it allows for simpler and more flexiable access to the buckets
        additioanlly, this design allows for better scalability and performance, as s3 can leverage the aws global network infrastructure to provide and fast and reliable access to the buckets
        however, its important to note that aws provides vpc endpoints for s3, which allows for secure and direct access to to s3 from within a vpc without going over the internet

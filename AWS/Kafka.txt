Apache Kafka
============

it is highly scalable and disributed platform for creating and processing streams in real-time.

structured streaming
====================
we used to read the data from a socket and then we used to process using apache spark

socket is nothing b\ut ip + port

socket does not have any buffering capability

if we have fast producer and a slow consumer then we will encounter data loss.

both producer and consumer are tightly coupled. - both should be in sync

Kafka will provide buffering capability

if a producer is producing at a very high speed. the consumer can still consume at its own pace.

using this we can get the producer and consumer decoupled

1.Kafka helps to create real time streams.
2.process streaming data (apache spark)

kafka can create and process streams but we mainly use kafka to create streams and process using apache spark

publisher-subscriber messaging system

pub-sub system

Broker - is nothing but a node/machine which is running a kafka software

if there are 5 brokers then we call it as a 5 node kafka cluster

producer can be -> twitter application
a Kafka cluster with multiple brokers (nodes/machines)
consumer can be -> spark streaming application

Kafka session-2
==================

Data integration platform
In the traditional messaging systems..
if there is a producer which produces the data..
if consumer consumes it then data is gone

in case of kafka we can have one producer and multiple consumers

the data is retained for 7 days by default

producer writes to the topic
consumer subscribes to the topic so it can pull whenever there is a new data in the topic

1.Producer - Data Producer (Twitter)
2.Consumer - Data Consumer (spark application)
3.Broker - a node which is running kafka software
4.Cluster - made of various brokers
5.Topic - a unique name which holds perticular data ex:tagging data or claims data
	if we keep this tagging data topic on a single machine then when the data grows over the time we may run out of storage
6.Partitions - a topic can be divided into partitions and each partition can be stored on a different machine (makes sys scalable and disributed)
	whenever we are creating a topic we need to define the number of partitions
7.Partition offset - Inside each partition, the messages are stored in a seqence and we have a seqence id.
if we want read perticular message, what details do we need?

	topic name as we may have many topics inside kafka cluster
	partition number as we may have many partitions inside each topic
	offset
	
8.Consumer Groups - 

1000's of billing counters all across the world. - 

your role is to get all these generated invoices and dump them to a file system / data center

producers are nothing but the billing counters

these all will go to kafka cluster

instead of putting more workload on one consumer , we create multiple consumers and call them as consumer groups

number of consumers in a consumer group should be equal to the number of partitions inside the topic

one partition cannot be handled by multiple consumers(if 2 consumers working on same partition then we dont know which consumer reads what and that can lead to dupes)
 however a consumer can take multiple partitions.

ex: 4 partitions and 2 consumers // each consumer can process 2 partitions

how to create a multi-node kafka cluster on local machine
===========================================================

3 brokers

server.properties
machine1 - broker1
broker.id=0
ip1:9092
/tmp/kafka-logs //where data will be present

server1.properties
machine1 - broker1
broker.id=1
ip1:9093
/tmp/kafka-logs1 //where data will be present

server2.properties
machine1 - broker1
broker.id=3
ip1:9094
/tmp/kafka-logs2 //where data will be present

copy server.properties and make different copies and change the broker ids, log dirs and listeners


ideally kafka broker run on port 9092

each broker should have a different IP

if we want to create a 3 node kafka cluster we will have to assign the different port number as IP will remains the same (3 brokers on local machine)

open the server.properties
broker.id=0
listeners=PLAINTEXT://:9092
log.dirs=/tmp/kafka-logs

now start the 3 nodes

./kafka-server-start.sh ../config/server.properties //starts broker1
./kafka-server-start.sh ../config/server1.properties //starts broker2
./kafka-server-start.sh ../config/server2.properties //starts broker3

create a new topic with three partitions

./kafka-topics.sh --create --topic dbsro_tagging --bootstrap-server localhost:9092 --partitions 3 --replication-factor 1

dbsro_tagging with 3 partitions

we have 3 brokers
dbsro_tagging-0
dbsro_tagging-1
dbsro_tagging-2

this means each broker is holding one partition

cat customers.csv | wc -l //12434

./kafka-console-producer.sh --broker-list localhost:9092 --topic customers < ../../../Desktop/customers.csv

./kafka-console-consumer.sh --bootstrap-server localhost:9092 --topic customers --from beginning --group customer-group

this one processed 8432 messages

./kafka-console-consumer.sh --bootstrap-server localhost:9092 --topic customers --from-beginning --group customer-group

this one processed 4002 messages

here we have two consumers and both are reading from same producer topic and good thing is that they both dont read same data.

this is how we make use of consumer groups to scale the process

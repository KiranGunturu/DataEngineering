Hive is an open-source datawarehouse and it is part of the larger hadoop ecosystem

hive runs on top of hadoop core.

hive stores its data in HDFS.

hive runs all processes in the form of MR jobs under the hood.

hive will translate the query to MR tasks and run them on hadoop (cluster)

MR will process files on HDFS and return results to hive.

Data - HDFS in the form of files
Metadata (schema) - in metastore (database)

when we query the table then this schema is imposed on the data and we see a tabular view.

Any database with JDBC driver can be used as a metastore.

Hive VS RDBMS
==============
======                             =============
Hive                                RDBMS       
=======                            ===============

Large datasets						Small datasets

parallel computations				serial computations

high latency						low latency

read operations						read/write operations

not ACID compliant by default		ACID compliant

HiveQL								SQL

schema-on-read						schema-on-write

seek time - time taken to fetch one individaul record.

low latency - if seek time is less then we say low latency operations. (RDBMS)

high latency - if seek time is high (data warehouses)

rdbms is schema on write

1. we create a table in mysql
2. we insert the data.

while writing the data in table, it is validating the things.

hive is schema on read

1. we already have the data in the form of files
2. we create the table stracture on top of above data to see in tabular format.

=============
Normalization
=============

when we talk about traditional databases , what is the problem with duplicate data or redundancy?

if same data is kept at multiple places and if we do update and forget to update that value at one place then data will become inconsistent.


it is the process of dividing a bigger table into multiple smaller tables with an intention to remove redundancy data.

1NF
2NF
3NF
BCNF
4NF

positives if Normalization.

no inconsistency issues.
less storage required as we are removing the duplicate data (redundancy)

negatives of Normalization.

you have to join multiple tables.
joining is very complex and time consuming activity.

=====Hive====

Normalization is not preferred in Hive.

Denormalization is preferred in hive.

Denormalization : store the data not in granular form rather bigger tables even if redundancy is there.

do not worry about redundancy
rather worry about storing the data in less number of tables

if we make updates we can run into data inconsistency issues?

	hive is not a system meant to do updates.
	since we do not update the data we won't run into inconsistency issues.
	
	but as we are maintaining redundancy it takes more space but that is ok as storage space is very cheap and if we spend little more storage then its not a big deal.
	
advantage to keep data in denormalized way in hive is that we do not have to operate the joins.

out intention is to minimize the joins because joins take time.

=======
Denormalized storage
===========

disk space is very cheap
no foreign key constraints.
read operations , no data updates

optimize the number of disk seeks (as there are not many tables joining)
do not worry about redundancy but minimize joins.

		--create table
		
		create table if not exists products (
			id string,
			title string,
			cost float
			)
		row format delimited
		fields terminated by ','
		stored as textfile;
		
		-- run below command in hive terminal to load the data
		
		load data local inpath 'home/cloudera/Downloads/products.csv into table products;
		
		--to overwrite the table data.
		
		load data local inpath 'home/cloudera/Downloads/products.csv overwrite into table products;

		it is like copy and paste - we will have the file in local even after data loading.
		
		since we did not mentioned the db name when creating the table , data will goto default path /user/hive/warehouse

Managed table

	table is by default managed table.

	hve has the complete control of your data also.

Hive UDF
===========

trim(), concat() etc - sys defined functions


if we want to customize something the we need to write UDF.

consider you have a table called sample_table with 2 columns

col1 - name
col2 - count

name (string), count(int)

Kiran	200
Krish	300
James	400
Michael 500


lets convert all the names to upper case.

we will be writing a UDF to convert all the names to upper case.

write below java code and create jar file.


package udf_example;

import org.apache.hadoop.hive.ql.exec.UDF;

public class DataStandardization extends UDF {

public String evaluate (String input) {

if(input==null)
{
retun null;
}
return (input.toString().toUpperCase());
}}

now we gor the jar file called udf_example.jar

now we need to add this jar on hive.


In hive terminal, we need to add the jar and also we need to register the function

Add JAR /localpath/udf_example.jar

create temporary function standardize as 
'udf_example.DataStandardization';


select standardize(name) from sample_table;

how do we make this permanant?

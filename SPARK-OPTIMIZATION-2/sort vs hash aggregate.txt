sort vs hash aggregate
=======================

order_id,order_date,customer_id,order_status
1,2013-07-25 00:00:00, 11599,CLOSED
2,2013-08-25 00:00:00, 256,COMPLETE

we want to find the number of orders which are placed by each customer in each month.

grouping is based on customer_id and month and find the count of number of orders


spark.sql("select customer_id, \
					date_format(order_date,"MMMM") as ordered_month, \
					count(1) as cnt, \
					from orders \
					group by customer_id, ordered_month").show()

now sort based on the ordered_month


spark.sql("select customer_id, \
					date_format(order_date,"MMMM") as ordered_month, \
					count(1) as cnt, \
					from orders \
					group by customer_id, ordered_month order by ordered_month").show()
					
above query will sort the ordered_month based on the alphabet means august comes first

final query - sort aggregate

spark.sql("select customer_id, \
					date_format(order_date,"MMM") as ordered_month, \
					count(1) as cnt, \
					first(date_format(order_date,'M')) as monthnum, \
					from orders \
					group by customer_id, ordered_month order by cast(monthnum as int)").explin()
					
					
					
this query takes 3.9 minutes

now lets modify this a bit

final query - hash aggregate

spark.sql("select customer_id, \
					date_format(order_date,"MMM") as ordered_month, \
					count(1) as cnt, \
					first(cast(date_format(order_date,'M') as int)) as monthnum, \
					from orders \
					group by customer_id, ordered_month order by monthnum").explain()
					
this query will only take 1.2 mins

2 questions
==============


1. difference between sort and hash aggregate
2. why in query one it used sort aggregate and why in query two it used hash aggregate?


property is that sort aggregate takes more time than hash aggregate

first the data is sorted based on the grouping columns.

sorting of data takes time.

to sort 1000 elements

o(nlogn)

1000 * log(1000)

1000 * 10 = 10000 operations

sorting of data takes time when the data grows

if we double the data time required to sort the data is more than doubled

to sort 2000 elements

o(nlogn)

2000 * log(2000)

2000 * 11 = 220000 operations


hash aggregate
===============

hash_table
=============
key					 value
customer_id:ordered_month		count			monthnum
1024:january 				3 			1
1025:january 				2 			1

no sorting is required as it just increments the count value as soon as it sees same key combo

additional memory is required to have the hash_table kind of structure.


1000 rows


sort aggregate - nlogn = 1000 * 10 = 10000 operations
hash aggregate - o(n) = 1000 operations.


this hash table kind of structure is not part of container rather this additional memory is grabbed as part of off-heap memory...

this memory is not part of JVM

2) why first query used sort aggregate and second one used hash aggregate
==============================================================================

==slower

spark.sql("select customer_id, \
					date_format(order_date,"MMM") as ordered_month, \
					count(1) as cnt, \
					first(date_format(order_date,'M')) as monthnum, \
					from orders \
					group by customer_id, ordered_month order by cast(monthnum as int)").explin()




==faster

spark.sql("select customer_id, \
					date_format(order_date,"MMM") as ordered_month, \
					count(1) as cnt, \
					first(cast(date_format(order_date,'M') as int)) as monthnum, \
					from orders \
					group by customer_id, ordered_month order by monthnum").explain()
					
in our sort aggregate case

month number was string

string is immutable

where as in the hash aggregate cnt and monthnum both are mutable types.

when we are using hash aggregate we should have mutable types apart from groupby columns

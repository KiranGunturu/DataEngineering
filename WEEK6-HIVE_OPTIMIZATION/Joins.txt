internally a join is executed as a MR job.
mapper will give the join columns as the Key.
and mapper gives all the other columns as the values.
Key - Join column
value - all the remaining columns.

1. try to minimize the number of join columns if possible. because if we minimize the join columns there will less MR jobs.
2. both bucketing & partitioning helps you to optimize the jobs. try to do it join columns.

Question:

can a full outer join be treated as a map side join provided the left table is small enough to fit in memory and the right table is large?

conclusion is NO as full outer join is combination of left and right outer.

if anyone of them do not work(left join) then full outer join can't be treated as map side join.


WHEN LEFT TABLE IS SMALL------

INNER JOIN CAN BE MAP-SIDE JOIN.
LEFT JOIN CANNOT BE MAP-SIDE JOIN.
RIGHT JOIN CAN BE MAP-SIDE JOIN.
FULL OUTER JOIN CANNOT BE MAP-SIDE JOIN.

WHEN RIGHT TABLE IS SMALL------

INNER JOIN CAN BE MAP-SIDE JOIN.
LEFT JOIN CAN BE MAP-SIDE JOIN.
RIGHT JOIN CANNOT BE MAP-SIDE JOIN.
FULL OUTER JOIN CANNOT BE MAP-SIDE JOIN.

==============
Map side join
==============

before the MR job is executed, there is local task which is executed.

1.this local task will take the small table and create a hashtable for this small table.

2.once the hashtable is created it will be put of hdfs.

3.from hdfs this hashtable is broadcasted to all the nodes.

4.when this hashtable is copied on the nodes, it will be existing in the local disk of each node. this sometimes also called as distributed cache.

5.hashtable is loaded in memory of the each node. so from local disk on each node it is loaded in memory.

after all the above steps, MR job starts after this.

constraint here is that entire small table is loaded into memory.

==========================
SORT MERGE BUCKET MAP JOIN
==========================

1.unlike map side join it can be done on 2 big tables also.
2.both the tables should be sorted on join column.
3.both the tables should be bucketed on join column.
4.number of buckets in both the tables should be exactly equal.
5.there will be one to one mapping between buckets in both the tables and 
a quick joining can be performed as both the buckets have sorted data.

MAP SIDE JOIN:
There is no reduce phase. the entire joining activity will happen at the mapper end.

can we always have a join as map side join?

however if certain criteris match then we can go for mapside join.

we want to join 2 tables.

=> out of 2 tables , one should be smaller so that it can fit in memory of datanode.

we want to join 3 or more tables.

all the tables except one or smaller to fit in memory.

now consider we have 2 tables.

1.orders
2.customers

one of them is big table and other is small.

1) sqoop import to get orders and customers table data from mysql to hdfs.
2) create external tables on top of that data.


select count(*) from orders - 68894
select count(*) from customers - 12435

set hive.auto.convert.join; it will give what is the current value of this property.

set hive.auto.convert.join=false; setting it to false to avoid map side join by default so we can see if it is invoking any reducers.

now try running the below query

select c.customer_id,c.customer_fname,c.customer_lname,o.order_id,o.order_date from orders o join customers c on
(o.order_customer_id = c.customer_id) limit 10;

now this will take 2 mappers and 1 reduce.

now let us try to execute inner join as map side join

set hive.auto.convert.join=true;

select c.customer_id,c.customer_fname,c.customer_lname,o.order_id,o.order_date from orders o join customers c on
(o.order_customer_id = c.customer_id) limit 10; - now the reducers are 0 as system wil automatically convert the join to map side if it can accomdate the small table into 
memory.

what is the definition of small table?

by default less than 25mb is considered to be small table.

set hive.mapjoin.smalltable.filesize;
25000000

in the previous case since we set the property then hive was automatically converting the join as map side join.

but what if we do not want to go with automatic conversion rather we want to specify using some hints.

set hive.auto.convert.join=false;
set hive.ignore.mapjoin.hint=false; - we are disabling the auto join feature by setting these two params but we will use hint.

/*+ MAPJOIN(o) */ -- hint to the system.

select /*+ MAPJOIN(o) */ c.customer_id,c.customer_fname,c.customer_lname,o.order_id,o.order_date from orders o join customers c on
(o.order_customer_id = c.customer_id) limit 10;

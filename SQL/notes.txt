with cte as (
select *,
row_number() over(partition by dept_id order by salary desc, emp_name asc) as rn
from employee
)
select *from cte
where rn<=2

here if there are two emps in the dept has same salary, only one emp gets in the o/p becuase rank for the second emp is differs.

so we use rank()
assigns the same rank and skips the next rank

with cte as (
select *,
rank() over(partition by dept_id order by salary desc, emp_name asc) as rn
from employee
)
select *from cte
where rn<=2


with cte as (
select *,
rank() over(partition by dept_id order by salary desc, age asc) as rn
from employee
)
select *from cte
where rn<=2

in above sql, if two emps have same salary then we are assigning rank based on emps lesser age will get next rank (2) and emp with
higher age gets next rank(3)

dense_rank()
assigns the same rank for dupes but do not skip the next rank

with cte as (
select *,
dense_rank() over(partition by dept_id order by salary desc, emp_name asc) as rn
from employee
)
select *from cte
where rn<=2

with month_wise_sales as (
select 
	datepart(year,order_date) as order_year,
	datepart(month,order_date) as order_month,
	sum(sales) as total_sales
	from orders
	group by datepart(year,order_date),datepart(month,order_date)

)

select order_year,order_month,total_sales,
	sum(total_sales) over (order by order_year,order_month rows between 2 preceding and current row) as running_sales
	from month_wise_sales

indexing
=========
it maintains the physical order of the data in the disk
uses binary search instead linear search (root , data pages along with range)
when we create an index, data will be sorted in a bitmap or Btree structure.
we can specify the sorting order when we create an index.
full scan if no index

clustered index
one only one of sorting the data in the disk
one clustered index on table but it can be of composite PK
bit faster.

non-clustered index
new structure will be created like hashmap
takes more space due to extra table structure called hashmap
if we create non-clustered index on emp_id, then every emp_id will have its own address in the hashmap

1 0x4r34
2 0X858t

sql engine will first search the hash map and get the corresponding to search in the actual table
bit slow as it is a two step process
it can have more than one index defined


43% cost to 0.09% when we create the index vs no index
